# 停止自動検証の仕様

停止の採用条件は既存の到着8cm、接地滑り2cm、床貫通2cm、骨長2mm+1%、フレーム間ルート6cmを維持する。診断は全項目を収集し、不正配列の場合のみ形状検証で終了する。身体基準の膝方向を使い、旋回と膝反転を区別する。

再現データには全履歴と履歴の時間刻みを保存する。候補生成器は新しい再生器を返すファクトリーを必須とする。共有GPUエンジンの状態まで復元できると未検証のまま主張しない。候補数は最大24、通常動作への適用は実モデルの回帰検証後とする。合格候補がなければ採用結果を返さない。

診断の足高は校正済みSOMA骨代理点であり、VRMメッシュの接触保証ではない。Idle連続性は末尾の安定性で評価し、別のIdleクリップとの遷移検証とは区別する。

## 実装状況と制限

全9項目の同時診断、接地区間の累積滑り、身体基準の膝方向比較、履歴JSONの読み書き、独立再生器を要求する汎用候補評価、保存配列からのHTML/JSON出力を実装した。`MOTIONBRICKS_STOP_REPLAY_DIR` を指定すると停止生成前の姿勢・全履歴・時間刻み・骨格・床・目標を保存する。

Phase 1〜7の完了ではない。GPU乱数・モデル版・VRM変換・歩行制御状態の完全保存、公式生成器用の候補ファクトリーと探索方針、ライブへの安全な統合、12状況の実推論回帰は未実装。履歴保存だけで完全再現可能とは扱わない。通常停止は従来の生成経路を維持する。足首診断は全関節のフレーム間回転差を含み、解剖学的な可動域判定は未実装。遊脚診断の採否は着地のみで、持ち上げ不足の判定は未実装。

`backend/stop_test_report.py replay.json --output metrics/stop-tests` は metadata に frames を含む保存配列を再診断する。停止前の自動保存ファイルには生成結果がまだ無いため、そのままこのCLIへ渡せない。

検証: Python 110件、JavaScript 27件成功。HTML/JSONは合成姿勢3ケースであり実モデルの成功率ではない。自動画面撮影では既存の停止失敗表示を確認したが、修正後のVRM映像品質は未検証。
