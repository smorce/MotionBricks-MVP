# 停止→待機の再設計（2026-11-01）

## 前回の失敗
前回の StopFootPlant は停止指示の時点で足首を世界座標に固定し、離地してもロックを解除しなかった。キャラクターの腰が進むと足を引っ張り、膝が過伸展した。停止→生成ポーズではロックも突然解除された。以前の SettledIdle は IK で着地を強制しており、同じ足に複数の処理が作用していた。

## 新しい所有権
- **moving / stopping**: MotionBricks がフレーム・最後の一歩・公式停止遷移を所有する。ブラウザは従来どおりスライダー9.5度の補正を適用。足首のワールドロックや追加 IK は行わない。
- **standing idle（open-floor）**: 公式の待機ループに到達するまで生成ポーズを要求しない。最後の表示フレームを一度だけ記録。脚・腰・シーンルートを固定し、上半身にだけ小さな呼吸動作を重ねる。スライダーは既にスナップショットに含まれるので重ね掛けしない。
- **再移動**: 保存した姿勢と MotionBricks の歩行姿勢の関節回転を240msでつなぐ。ルートは MotionBricks の入力で動かす。
- **特定動作（着席等）**: 明示的に選択されたユースケースに対して従来の生成ポーズ遷移を保持する。停止脚の固定を生成ポーズに重ねない。

## 限界
MotionBricks 内部の停止クリップが最後の接地で足をスライドさせる場合、それは今回のスナップショットだけでは消せない。最後の一歩を確定させる厳密な接地判定には、足裏位置・速度・床法線をモデルごとに取得して検証する必要がある。立ち姿勢の足幅を無条件にアイドル素材の足幅に合わせる処理や、踏み直しアニメーションの合成は行わない。

## 実機検証
1. Windows / RTX 4090 の公式 Scene Preview で歩行→停止の出力を確認。
2. ブラウザで open-floor をクリックし、移動中に9.5度の脚補正が保持されることを確認。
3. 停止直前の接地足の床上X/Z移動、足先の高さ、および姿勢保存時の段差を動画で測定。
4. 同じ場所から再移動し、240ms の姿勢移行と腰の位置変化を確認。
5. 特定ポーズのユースケースは従来の挙動を保つことを確認。

検証コマンド: `python -m unittest discover -s tests -v` （環境内で）、`node --test web/src/groundedIdle.test.js` （web で npm install 済みの場合）。
