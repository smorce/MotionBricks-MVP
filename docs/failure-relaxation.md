# 停止生成失敗後のゆっくりした待機移行

チェックポイント01を保持し、`fix/stop-failure-idle-relaxation` で追加した実験。
対象は通常の `prepared` 方式の停止生成が採用できず、姿勢保持に入る場合。
成功したF001停止の経路と固定5パターンは変更しない。

## 動作

失敗直前の姿勢と履歴から独立したSOMAキャラクターを作り、公式のIdle移行を一度生成する。
公式ランタイムに `decelerating` という独立状態はない。アプリの減速状態と区別し、
今回は移動入力を止めた際の公式Idleへの移行を使う。
待機目標が先へ飛ばないよう生成用の実速度をゼロにし、現在の向きを渡す。

保持姿勢から最初の1秒で滑らかに混ぜ、公式の時間を0.5倍速で進める。
非ルートのローカル位置は現在の骨格寸法を維持し、姿勢の回転を移す。
接地中の足は既存の公式IKアンカーで補正する。生成後のルート平行移動は行わない。
骨長と有限値を確認した区間を、既存の単一推論プロセス・確定フレーム供給で再生する。
この経路は到着条件の再探索ではなく、失敗後に立ち姿勢を落ち着かせるための移行。

`stop_failed → stop_relaxing → stop_relaxed` と進み、移行後は最後の待機姿勢を保持する。
元の停止失敗理由、目的地、停止生成の不合格は残し、`settled` や到着成功にしない。
待機移行そのものも生成できない場合は、再試行を繰り返さず元の保持へ戻る。
新しいクリックで待機移行の状態を破棄し、表示中の姿勢から通常の移動を開始する。

## 確認

通常画面上部の「停止失敗後のゆっくり待機移行を確認」または
`http://127.0.0.1:5188/stop-distance-lab.html?prepared&relaxation` で固定例を再生できる。
例は目的地まで約4.08cmの保存された接続元から生成したもの。
この例の再生時間は約4.27秒、ルート変位は約3.63mm、終端の目的地誤差は約4.43cm。
数値はこの1例の記録であり、全姿勢での足滑りや自然さ、5cm以内の維持を保証しない。
自然さは目視で判断する。元の停止検証の条件は緩和していない。
その後の採用条件の選別は [F001停止条件の選別](prepared-stop-acceptance.md) を参照する。

ライブでも4cmのクリックで失敗状態から `stop_relaxing` を経て `stop_relaxed` に進むことを確認した。
回帰テストでは一度だけの生成要求、失敗記録の維持、再クリック時の初期化、
待機移行自体の失敗時の保持、ブレンド開始姿勢と骨格寸法を確認する。

再現用CLIは `backend/probe_failure_relaxation.py --source <停止生成の記録JSON> --output <目視用JSON>`。
公式ランタイム環境からuv経由で実行する。通常再生と同じく、推論時間分の準備待ちは発生し得る。
