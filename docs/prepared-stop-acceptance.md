# F001停止条件の選別

対象は通常の `prepared` 方式。チェックポイント01の方式と条件を比較可能にし、
以前の `visual` 方式・オフラインの検証器は変更しない。

## 方針

停止の自然さをコードで認定しない。採用に使う最低限の異常検出と、目視のための診断を分離する。
閾値の数値を緩めて合格させる変更ではなく、自然さの推測を採用拒否の根拠から外す。
以下のガードも、人間の評価と照合して精度が証明された分類器ではない。測定の意味が明確な暫定ガードとして扱う。

| 採用に残す条件 | 役割と限界 |
| --- | --- |
| 姿勢配列の形、必要フレーム数、有限値、有効な四元数 | 再生できないデータを拒否する |
| 元姿勢に対する骨長維持 | 骨格寸法の破損を防ぐ。既存の2mm＋骨長1%の許容値を維持 |
| ルートの1フレーム変位6cm以内 | 接続元を含めた位置の飛びを抑止する。60Hzでの現在値 |
| 関節の1フレーム回転差0.35rad以内 | 正規化した四元数の差で急変を検出する |
| 校正済みSOMA床への侵入2cm以内 | 骨格上の床侵入を検出する。描画された靴底との一致は保証しない |
| 終端で両足が校正床から4cm以内 | 空中の最後の一歩を停止完了として保持しない。接地信頼度ではなく校正高さを使う |
| 元の目的地との終端誤差5cm以内 | 合意した到着許容値。自然さの指標ではない |

膝角度、足裏の向き、推定接地中の滑り、遊脚の持ち上げ高さ、終端4フレームの足の微動、
最小前進量・前後方向の通過判定は診断に残す。これらだけでは採用を拒否しない。
足滑りの測定は公式接地信頼度と高さ推定に依存するため、滑りの数値と画面を照合して判断する。
接地アンカーによる公式IK補正そのものは維持する。

## 選別の根拠

今回調べた直近150件の `prepared_f001` 記録は、すべて元の目的地から終端誤差5cm以内だった。
そのうち7件は従来の姿勢・接地検証を通り、進行検証だけで拒否されていた。
最初の選別では回転の急変だけで11件を拒否したが、終端で足が浮いている例も9件あった。
これを停止完了として保持すると最後の一歩で固まるため、終端の床近傍条件は残す。
同じ150件を固定して最終方針と比較すると、旧採用65件、新採用130件、拒否20件。
新たに通る65件に人間の自然さ評価を付けたことにはならない。
「目的地の許容範囲にいるのに1cm以上の前進が足りない」という矛盾した拒否を確認している。
停止失敗後の公式Idle移行でも、ゆっくりした姿勢変化を別の動作として再生できた。
終端数フレームの微動や一律の遊脚高さだけで自然さを判断する根拠は不足している。

記録の拒否数は不自然さの正解ラベルではない。今回の5パターンへの全体的な好評価を、
保存された全候補の個別評価として転用しない。選別によって新たに採用される動作の自然さは目視確認を続ける。

## 実装と記録

`backend/prepared_stop_acceptance.py` が診断結果から `hard_failures` と `warnings` を分離する。
`VisualStopRuntime.generate` は `prepared` の場合だけこの方針を使う。
元の検証結果・進行拒否理由は保存し、実際の採用方針も別に記録する。
採用不能な場合の、ゆっくりした公式Idleへの移行は引き続き使用する。

歩行中の進路補正、横ずれ5cm以内での停止開始、進行方向を固定した生成用目標は変更しない。
生成後のルート平行移動は行わない。移動要求ID・接続元の整合性検証も維持する。

保存診断の比較は `backend/audit_stop_acceptance.py --output <JSON保存先>` で再現できる。
既定は `metrics/visual-stop-runs` の数値名ファイルから直近150件の `prepared_f001` を選ぶ。
`--reference-audit <以前の比較JSON>` を指定すれば、同じファイル群で比較を繰り返せる。
推論・生成結果の書き換え・人間評価の付与は行わない。
