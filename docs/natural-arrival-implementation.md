# 停止準備からF001へ接続する到着制御

チェックポイント01の現行仕様と停止条件の信頼性に関する判断は、[アーキテクチャ仕様書](architecture-checkpoint-01.md) を正とする。本書の性能比較は開発途中の計測記録であり、現在の全入力を保証するものではない。

チェックポイント01以降の変更として、[失敗後の待機移行](failure-relaxation.md) と [F001停止条件の選別](prepared-stop-acceptance.md) を参照する。通常の新実験では、後者に記載した最低限の採用ガードと診断の分離を適用する。

## 対象と到着仕様

通常の床クリックは「停止準備 → F001接続（新実験）」を使用する。従来方式の自動検証結果を、この方式の完了判定には使用しない。画面から従来方式を除き、停止方式を省略したクライアントおよび古い従来方式の指定も新実験へ移す。厳密な目視候補照合と特定の到着動作は維持する。

元のクリック位置を変更せず保持し、歩行中に横ずれと実測進行方向を使って進路を連続補正する。旋回速度は毎秒2radまでとする。低速の腰の揺れは進行方向に採用せず、直前の有効な方向を保持する。

候補照合が停止可能でも、実測進行方向上のクリック位置との横ずれが5cmを超えていれば歩行を続ける。停止開始時に進行方向を固定し、その直線へクリック位置を射影したF001目標を作る。生成後のフレーム全体を平行移動して到着位置へ合わせる処理は行わない。到着は元のクリック位置から5cm以内で判定し、到着位置合わせのための追加停止区間を再生しない。

## F001生成と接地

新実験ではF001接続だけを生成する。歩行速度に応じて最大1.2m手前から停止候補を先行生成し、接地・骨長・膝・連続性・終端安定性・元の目的地との距離を検証してから採用する。失敗した未再生の候補は破棄し、歩行を進めた別の接続元から再検証する。採用後は候補探索に戻らない。安全な候補が得られなければ `stop_failed` とし、成功扱いにはしない。

F001のA方式は足を一歩も動かさず固定する方式ではない。そのため、従来の固定支持足検証を適用せず、公式接地信頼度と床の高さに基づく各接地区間の累積滑りを検証する。接地検証の2cm閾値は緩和していない。

接地中の足には公式IK補正器で区間開始位置を保持させ、離地時には4フレームで補正を解除する。床への侵入は足のIK目標の高さで補正する。表示するルートは移動させず、独自の骨伸縮は使用しない。補正後にも骨長、関節連続性、床、足滑り、着地を検証する。

## 生成・配信・描画

GPU推論は単一の生成プロセスが直列に行う。表示供給側は確定済み区間を60Hzで配信し、その再生中に生成側が将来の接続元姿勢と履歴から停止区間を作る。生成側が表示中のキャラクターを別スレッドから変更する構成にはしない。

配信には連番、移動要求ID、シミュレーション時刻を付ける。画面側は100msの時刻バッファで補間し、欠損時は検証済み終端を保持する。再クリックでは表示中の連番と移動要求IDに対応した姿勢・履歴・移動状態を復元する。失効した要求や照合できない接続元の結果は採用しない。

候補の参照履歴特徴量は事前計算し、現在状態の特徴量を照合内で共有する。大きな姿勢履歴とレビュー資料は毎フレーム配信せず、詳細な生成記録は有界キューを使う別の保存スレッドへ渡す。Windowsの配信時刻には高分解能タイマーを使用する。

## 実モデルで確認した原因と判断

- 新実験の候補照合経路が横ずれの停止条件を迂回していたため、同じ条件を適用した。
- 足を固定しないA方式へ固定支持足用の検証が適用されていた。固定支持足と接地区間の滑りを区別した上で、実際に測定された滑りを公式IKで抑えた。
- 固定の急な解除によって足首・膝が急変したため、離地時の補正解除を連続化した。
- 低速時の腰の揺れを進行方向と誤認すると、歩行補正が逆向きへ入った。十分に移動している履歴だけを方向推定に使う。
- 1.2m手前で横ずれ5cm以内に合わせるには、方向差を約2.4度以内に抑える必要がある。歩行生成の方向更新閾値が5度では補正が反映されない場合があったため、1度へ変更した。
- 近距離の再試行で同じ姿勢から生成し続ける経路があった。未採用候補の後には歩行フレームを進める。
- 連続クリック後の接続元ですでに浮いていた足が、生成後だけの高さ集計により離地不足と判定されていた。開始姿勢の離地高さも集計し、2.5cmの離地閾値自体は維持する。
- 目標近傍でも、大きく通過して戻る停止を到着成功にしない。
- 初期スナップショットが古い場合は現在の配信時刻へ再同期し、100msのバッファが古い時刻に引きずられることを防ぐ。単発の移動拒否は、後続接続に対する恒久的なエンジン障害として保存しない。

## 再現方法

ユニットテストはプロジェクトルートで次のコマンドを使用する。

```powershell
$env:PYTHONPATH='backend;tests'
uv run --no-project --python 3.12 --link-mode=copy --with numpy --with fastapi python -m unittest discover -s tests
node --test web/src/*.test.js
```

実モデルの連続移動は `backend/benchmark_arrival.py --output <JSONの保存先>` で再現する。公式ランタイムの環境からuv経由で実行する。詳細な候補・生成元・検証値は `metrics/visual-stop-runs/` に保存される。

ブラウザーは `docs/ai-browser-observation.md` のPlaywright設定を使用し、`web/benchmark-browser.mjs` と `web/benchmark-scenarios.mjs` を実行する。前者は新実験を明示選択して床クリックと基本移動を測定し、後者は左右のずれ、長距離、連続クリックと三方向のデバッグ画像を記録する。性能計測中にはスクリーンショットを取得しない。

自然さの主観評価はユーザーが行う。コードの停止条件は自然さの判断として信用せず、検証合格と人間評価を区別する。検証記録の対象と未確認事項は `metrics/natural-arrival/verification-summary.json` を参照する。

## F001接続での性能比較

同じRTX 4090端末、Chromeヘッドレス、1440×1000、カフェ表示、初期待機姿勢で比較した。両方とも新実験を明示選択し、5秒のウォームアップ後、同じ相対クリック列を10秒間隔で与えて60秒計測した。計測中の撮影や他の推論実験は行わない。移動要求直後の準備待ちは再生中のフレーム間隔に含めない。

| 項目 | 修正前（278e6d4） | 修正後 |
| --- | ---: | ---: |
| 描画間隔P95 | 16.9ms | 16.8ms |
| 描画間隔最大 | 700.1ms | 17.1ms |
| 再生中の配信間隔P95 | 28.21ms | 17.61ms |
| 再生中の100ms超の配信停止 | 5回 | 0回 |

比較の原データは `browser-prepared-baseline.json` と `browser-prepared-comparison.json` に保存した。接地の実モデル検証はSOMAの校正済み足ボーンと公式接地信頼度を用いる。描画された靴の形状や歩容の自然さは、この数値だけでは判定しない。
